# 🎮 Lista de Jogos (Game List)

**EN** · Static page with the list of games I have played — dark/neon theme, bilingual (PT-BR / EN). Frontend on [GitHub Pages](https://pages.github.com/), API on Cloudflare Workers, data in a PostgreSQL database on [Neon](https://neon.tech).

🌐 **Versão em português:** [README.md](README.md)

## 🏗 Architecture

| Piece                 | What it does in the project                                                                                       |
| --------------------- | ----------------------------------------------------------------------------------------------------------------- |
| **GitHub + Pages**    | stores the code and publishes the frontend (HTML, CSS, JS) — static, no backend                                   |
| **Cloudflare Worker** | runs the REST API (`/api/games`), validates requests, applies CORS and returns JSON                               |
| **Neon**              | hosts the PostgreSQL database: `games` table, metadata, ratings and reviews                                       |
| **Hyperdrive**        | optional — only needed with a TCP driver (node-postgres). With Neon's serverless driver (used here), not required |

Flow: `Pages (static) → Worker (REST API) → Neon (PostgreSQL)`.

### Fields per game

- `title` — the game's **original** title (as released, usually in English)
- `title_pt` — optional: the title as released in **Brazil**, shown when the language is PT-BR
- `year`, `platform`, `engine`, `rating` (1–5 stars), `company`, `genre`, `mode`
- `review` — optional: your written review, shown in the modal when clicking the card
- `cover` — not stored in the database: it is an `assets/covers/<id>.jpg`/`.png`/`.webp` file
  in the repository itself (see [assets/covers/README.md](assets/covers/README.md)); without a cover, the card has no image
- Any `null` field simply doesn't appear on the page (shows "_a preencher_" / "_to be filled_" when there is nothing).

## ✍️ How to edit the data

- **On the site (recommended)**: click a game → fill in fields/stars/review → SAVE.
  With the API configured (⚙), this writes straight to PostgreSQL via `PATCH /api/games/:id`.
- **Through the JSON**: edit `data/games.json` (offline fallback). Any push that touches it
  makes the `sync-neon.yml` workflow upload everything to Neon automatically
  (`cd worker && node sync-db.mjs`). `node tools/generate-seed.mjs` regenerates
  `worker/seed.sql` if you need to rebuild from scratch.

## 🎨 Covers

One cover per game in `assets/covers/<id>.jpg`/`.png`, populated by `tools/fetch-covers.mjs`
(360/364 today). Sources, in order: **Steam CDN** (`library_600x900`), **Libretro
Thumbnails** (retro consoles), **xero/boxart** (retro collection on GitHub), **SteamGridDB**,
**IGDB** and **TheGamesDB** (last, because of its monthly quota). Keys live in gitignored
files: `tools/.sgdb-key`, `tools/.igdb.json`, `tools/.tgdb-key` — or in environment
variables (`SGDB_API_KEY`, `IGDB_CLIENT_ID`/`IGDB_CLIENT_SECRET`, `TGDB_API_KEY`).
Wikipedia was dropped (low quality). The 4 games without covers are community-made content
(custom maps) or web games with no official art — they will get a custom screenshot/art.
Cards load **thumbs** (`assets/covers/thumbs/<id>.webp`, ~9 KB; regenerate with
`npm run thumbs`) — the modal loads the original, so zoom never loses quality.

Details in [assets/covers/README.md](assets/covers/README.md).

## 🛠 API (Worker)

| Route            | Method | Auth           | What it does                         |
| ---------------- | ------ | -------------- | ------------------------------------ |
| `/api/health`    | GET    | public         | status + total game count            |
| `/api/games`     | GET    | public         | full game list (JSON)                |
| `/api/games/:id` | PATCH  | `Bearer token` | updates fields of a game (whitelist) |

Write routes require a session opened via `POST /api/login` (password = the Worker's
`ADMIN_PASSWORD` secret, compared in constant time, returned as an **HttpOnly cookie**
signed with `SESSION_SECRET` — payload `iat.jti.exp`, HMAC-SHA256 — which the site's
JavaScript cannot read) or the `Authorization: Bearer <password>` header from a terminal.
Validation: `rating` 1–5, plausible `year`, texts ≤ 200 (review ≤ 4000) characters.

## 🧰 Code quality (formatting, linters and CI)

### Running locally

```bash
npm install      # first time only

npm run format   # formats everything (Prettier)
npm run lint     # reports JS and CSS errors
npm run lint:fix # auto-fixes what it can
npm run check    # formatting + lints — what CI runs (must be 100% green)
```

### Style rules

- Indentation: **2 spaces** (no tabs) in every file
- **Single** quotes in JS, always with `;`
- JS as **ES modules** (`type="module"` in `<script>`), `const`/`let` (never `var`)
- Strict comparisons (`===`/`!==`), CSS colors in modern notation (`rgb(... / 18%)`)
- GitHub CI blocks the push ❌ if anything breaks the standard — run `npm run check` first

## 🚀 Deploying to GitHub Pages

1. Create a GitHub repository (name suggestions below).
2. On your computer:

   ```bash
   git remote add origin https://github.com/YOUR-USER/REPO-NAME.git
   git push -u origin main
   ```

3. On GitHub: **Settings → Pages → Build and deployment** → Source: _Deploy from a branch_, Branch: `main` / `/ (root)` → Save.
4. In ~1 minute the page is live at:
   `https://YOUR-USER.github.io/REPO-NAME/`

> The repository already has a `.nojekyll` file, so Pages serves the files as-is (no Jekyll processing).

## ☁️ Bringing the backend up (Neon + Cloudflare)

The detailed walkthrough is in [`worker/README.md`](worker/README.md). Summary:

1. **Neon**: create the project, copy the connection string, run `worker/schema.sql` in the SQL Editor
   and `cd worker && DATABASE_URL=... node sync-db.mjs` (or let the `sync-neon.yml` workflow
   upload the seed on the first push).
2. **Cloudflare**: `cd worker && npm install && npx wrangler login`, configure the secrets (`DATABASE_URL`, `ADMIN_PASSWORD`, `SESSION_SECRET`) and run `npx wrangler deploy`.
3. **Site**: in the ⚙ of the page, paste the Worker URL and the password — login opens a 7-day session (HttpOnly cookie) and the site starts writing to the database.

Without an API configured, the site still works in **local mode** (reads `data/games.json`,
saves edits to the browser's `localStorage`). Reason for the fallback: the frontend is static.
